# Handleiding: feedback geven via GitHub Discussions

> Bedoeld voor kernteamleden die de showcase reviewen. Korte instructie
> voor wie GitHub Discussions niet dagelijks gebruikt.

## In één regel

Ga naar https://github.com/BronzGreen/aimm-content/discussions →
"New discussion" → kies categorie → schrijf je observatie → submit.

## Stap voor stap

1. **Open een discussion**
   - https://github.com/BronzGreen/aimm-content/discussions/new
   - Of: vanuit elke LO-pagina → klik onderaan "Open Discussion → LO-feedback"

2. **Kies de juiste categorie**
   - **LO-feedback** — opmerking over een specifiek leerobject
     (trainee/trainer/draaiboek/werkblad)
   - **KO-feedback** — opmerking over een specifiek kennisobject
     (de inhoudelijke laag onder een LO)
   - **Module-feedback** — opmerking over een hele module of leerbijeenkomst
   - **Algemeen** — procesvragen, vragen over de showcase zelf,
     suggesties voor structuur

3. **Titel-conventie**: begin met het ID + dubbele punt + korte
   omschrijving. Voorbeelden:
   - `LO-spc-101: regelkaart-uitleg te abstract voor MBO-3`
   - `KO-data-lit-101: voorbeeld onbekend voor lasersnijderij`
   - `Module-1c-i40: opbouw breekt rond werkblad 3`

4. **Body**
   - **Wat je opviel** — concrete observatie, niet alleen "vond het mooi"
   - **Waar precies** — bestand + regel of sectie als je kunt
     (bijv. "trainee.md, alinea 'Vier soorten data'")
   - **Optioneel: voorstel** — als je een verbetering ziet, schrijf het op.
     Maar geen vereiste; constateren is genoeg.

5. **Submit** — kennisteamleden + Landelijke Learning Lead krijgen een
   notificatie. Reactie binnen werkdag of twee.

## Wat we met je feedback doen

- **Tikfout of kleine correctie** → direct gefixt in de hoofdrepo
  (`BronzGreen/aimm`), bij volgende publish-ronde automatisch in
  showcase.
- **Inhoudelijke vraag op een KO** → issue op hoofdrepo met label
  `librarian-review`.
- **Didactische vraag op een LO** → issue op hoofdrepo met label
  `educator-review`.
- **Patroon over meerdere LO's** → input voor `aimm prompt-audit`
  cyclus.

Triage gebeurt wekelijks (vrijdag, ~30 min) door de Landelijke
Learning Lead. Je krijgt een korte ack in de Discussion zodra ik je
opmerking heb gezien.

## Tips voor goede feedback

- **Niet alles in één Discussion** — een reactie per "ding". Anders
  raakt het overzicht zoek.
- **Wees specifiek over wat klopt of niet klopt** — "voelt niet
  helemaal" is moeilijker te gebruiken dan "regel 14 zou ik weglaten".
- **Tijd om bij stil te staan ≠ tijd om perfect op te schrijven** —
  vier zinnen is genoeg.
- **Vragen mogen ook** — als iets onduidelijk is, is dat zelf al
  feedback. Geen verplichting tot "kan beter".

## Waar je géén feedback nodig is

- **Voor je iets goed vindt**: stille goedkeuring is OK. Geen Discussion
  als alles klopt.
- **Voor styling/typografie**: opmaakvragen los ik zelf op; focus op
  inhoud en didactiek.

## Privacy + zichtbaarheid

De repo is private — alleen ingenodigde kernteamleden zien je
opmerkingen. Geen openbare publicatie. Geen koppeling met sociale
media of externe systemen.
